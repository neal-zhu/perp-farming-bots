# Native margin configuration

This feature uses official protocols and the existing independently implemented adapters. It does not import another private project's code. Saving a grid performs read-only validation; only the user's Run command can apply native settings to a flat, unreserved account/market.

- [Arcus effective leverage](https://docs.arcus.xyz/api-reference/public/get-leverage-and-margin-mode-for-an-account-across-all-markets.md): GET `/v1/leverages` returns effective per-market leverage/mode, including market defaults. Validate address, subaccount, market ID/display name and the agreement between `isolated` and `marginMode`.
- [Arcus set leverage](https://docs.arcus.xyz/api-reference/exchange/set-leverage-for-a-market.md): POST `/v1/setLeverage` uses Ed25519 over nanosecond timestamp + `setLeverage` + compact sorted JSON body. HTTP 202 is an asynchronous acknowledgment, not confirmation. Read back effective settings even after HTTP 200. Cross-to-isolated requires flat native inventory; the application does not alter settings for allocated positions.
- [Arcus margin modes](https://docs.arcus.xyz/concepts/perpetuals/margin-modes.md): isolated margin is allocated to native positions, independently of unused account collateral. This feature does not automatically adjust isolated margin. Native `marginUsed` supplies the current isolated allocation; cross allocation stays explicitly unavailable.
- [Official Lighter read schemas](https://github.com/elliottech/lighter-agent-kit/blob/main/references/schemas-read.md): account `initial_margin_fraction` is a percentage (`50.00` means 2x); `margin_mode` is 0 cross / 1 isolated, with `allocated_margin` for isolated positions. A missing historical market row keeps current leverage/mode unknown.
- [Official Lighter signer](https://github.com/elliottech/lighter-python/blob/04bee9ba9811b87ef1cccc568e7f590b5fe649bb/lighter/signer_client.py): `sign_update_leverage` uses an integer fraction in 1/10,000 units (`2000` means 5x). We sign without using the convenience send method, journal the encrypted prepared transaction, then submit once through existing `sendTx`. Core chain 304 and Robinhood chain 466324 remain separate. Integers that cannot be represented exactly are rejected rather than rounded.
- [Binance Futures grid parameters](https://www.binance.com/en/support/faq/detail/f4c453bab89648beb722aa26634120c3): reference for the investment-margin/leverage model. This application's budget determines planned grid quantity; it does not reserve the entire amount upfront or reproduce Binance's managed bot wallet.

Market maximum leverage uses Arcus `initialMarginFraction` (decimal fraction) or Lighter `min_initial_margin_fraction` (integer in 1/10,000 units). Read-only probes verified the unit interpretation on 2026-10-13. For example, account IMF `50.00` represents 2x leverage; market limits and account settings must be read for the selected account/market rather than inferred from that example. Entropy's separate native setting contract is recorded in [Entropy evidence](entropy.md).

The single-send setting operation is confirmed by fresh native leverage and mode, never by an ACK/hash. A bounded confirmation window ends in an explicit unknown state, blocks grid execution and retains original evidence. Later synchronization reads only; confirmation pauses the bot for explicit user resumption. Active grids verify settings before strategy actions; allocated manual reduce-only close remains available if external settings change.
