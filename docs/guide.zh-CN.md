# 使用指南

安装方法见 [中文快速开始](../README.zh-CN.md)。默认打开 http://127.0.0.1:8080。一个程序可以连接多个账户、运行多个 Bot；同一交易所的不同账户也能分别连接。

## 连接账户

在“账户实例”点击“连接账户”，填写账户昵称，选择交易所。昵称只用于识别，例如“Arcus 账户 A”。

| 交易所 | 需要填写 | 获取位置 |
| --- | --- | --- |
| Arcus | 钱包地址、0–9 的子账户编号、API Signing Key | [Arcus API Keys](https://app.arcus.xyz/api-keys) |
| Lighter Core | Account Index、API key 编号、API 私钥 | [Core API Keys](https://app.lighter.xyz/apikeys) |
| Lighter Robinhood | 该部署的 Account Index、API key 编号、API 私钥 | [Robinhood API Keys](https://robinhoodchain.lighter.xyz/apikeys) |
| Entropy | 主交易账户地址、已授权的 API 代理私钥 | 先在 [Entropy](https://entropy.io) 完成交易授权，再在 [Hyperliquid API](https://app.hyperliquid.xyz/API) 创建有名称的代理 |

点击“验证并连接账户”后，程序先读取原生账户并检查授权，通过后才保存。这里使用交易 API 密钥，不填写钱包助记词或主钱包私钥。Lighter 的 Core 与 Robinhood 凭据不能互换。Entropy 暂不支持统一/组合保证金、子账户、Vault 和自有 HIP-3 合约。

账户实例代表真实账户身份。给同一原生账户换 API key 不会形成第二个独立账户。完整的身份定义和能力范围见 [交易所接入](exchanges.md)。

## 创建对冲 Bot

1. 点击“创建 Bot”，选择“跨账户价差对冲”。
2. 选择做多账户、做空账户和币种。两个账户必须不同，可以属于同一交易所。
3. 设置单侧目标金额、建仓价差条件和最大滑点，保存。
4. 点击“运行”。程序等待价差条件，确认第一腿实际成交后，再按已成交数量执行第二腿。

单侧目标金额是每条腿的名义金额，不是两条腿的合计保证金。策略沿用交易所的杠杆和保证金模式；资金检查要求可用抵押资产覆盖单侧目标金额。最大滑点限制订单价格，不能保证完全成交。

可以开启“定期重开”：双腿确认建仓后计时 → 间隔到期平仓 → 确认双腿平仓 → 随机等待 → 再检查原价差条件。随机等待上限可设为 0–5 分钟。暂停取消本次持仓计时；恢复后重新计时。手动平仓结束循环。

单腿、部分成交或数量不匹配会明确提示。程序保留实际持仓并查询原订单，不自动补腿或止损。规则详见 [对冲策略](hedging.md)。

## 创建网格 Bot

选择“永续网格”，绑定一个账户，填写方向、价格区间、网格数、保证金额度、杠杆和全仓/逐仓模式。

| 参数 | 含义 |
| --- | --- |
| 价格下限 / 上限 | 固定网格的边界；格线不会随当前价格整体移动 |
| 网格数 | 区间划分的份数；格数越多，相邻价格越接近，每份数量也更小 |
| 投入保证金额度 | 用于计算每格数量的资金预算；不会立刻把全部额度锁定 |
| 杠杆倍数 | 保证金乘以杠杆得到区间内名义仓位上限 |
| 保证金模式 | 全仓共享账户抵押资产；逐仓按实际持仓分配保证金 |
| 启动时建仓 | 做多/做空可选，默认关闭；开启后可能一次建立多格底仓 |

例如，保证金 $300、杠杆 3 倍，区间内名义仓位上限为 $900。这不是累计成交额上限；多次买卖后，累计成交额可以超过 $900。交易所最小数量、价格精度和取整会影响每格实际数量。价格超出区间后，已有仓位的市场价值也可能超过按区间算出的金额。

保存时自动检查余额、杠杆限制、最小订单和账户占用；参数不合格会留在表单中提示。保存不会修改交易所设置。点击运行时才应用所选杠杆与模式，读回确认后开始监测。

| 方向 | 启动和后续动作 |
| --- | --- |
| 做多 | 从空仓等待下跌买入，随后上涨减仓；不会转为做空。可开启启动底仓 |
| 做空 | 从空仓等待上涨卖出，随后下跌减仓；不会转为做多。可开启启动底仓 |
| 中性 | 从启动价附近的空仓格位开始，下跌逐格做多、上涨逐格做空；切换方向先确认平仓 |

开启启动底仓时，初始订单可能包含多份数量，以便上涨或下跌时逐格减仓。关闭时，每次价格触发才买卖一份；可使用的网格位数量取决于启动位置，未必会用满名义额度。

网格卡片展示当前价格、下一格买入/卖出价、距离和相邻格线。开启“全部格线”可查看整个计划。红色表示卖出，绿色表示买入；它们是程序内触发计划，**交易所没有提前挂单**。成交确认后策略推进到相邻格位，后续价格往返会继续增减仓。

程序需要持续在线。价格在区间外时保留仓位等待，不在区间外新增网格订单。网格独占该账户的该币种，不能同时交给另一个 Bot 或混入手动持仓。详细计算见 [网格规则](GRID.md)。

## 运行、暂停、平仓和修改

| 操作 | 结果 |
| --- | --- |
| 运行 | 启动或恢复策略；已确认平仓的 Bot 会重新开始一轮 |
| 暂停 | 保留仓位，停止新策略动作；恢复网格沿用原格线 |
| 平仓 | 只处理此 Bot 的分配数量；部分成交会保留剩余数量 |
| 修改参数 | 回填原参数；允许修改的字段由当前持仓、订单和状态决定 |
| 删除 | 需确认，且必须无持仓、无未确认操作；历史成交记录保留 |

运行中的网格要先暂停；有持仓时不能重置方向、区间、格数或资金配置。暂停/已平仓且无持仓、无未确认操作时可以修改。已有订单历史时账户和币种保持固定。保存新配置后需明确点击运行，才重新初始化。

关闭浏览器不会停止 Bot。停止程序会停止条件监测，但不会替你平掉交易所仓位。

## 看懂数据

- **交易盈亏**：价格盈亏扣除已确认手续费，暂不包含实际资金费。缺少必要证据时显示待确认。
- **累计成交额**：本 Bot 所有已确认成交的数量乘以成交均价之和，包括建仓、减仓和平仓。重复同步不重复累计。
- **资金费率**：市场的下次结算预估，不等于已到账资金费。页面显示预计支付/收取及周期。
- **积分**：当前只采集 Lighter Robinhood 自己账户的实时积分，每两分钟一次；提供 24 小时、7 天和 30 天曲线。失败、缺失或过期保持不可用，曲线上留空。其他交易所暂未接入。

## 状态与故障

| 显示 | 含义与处理 |
| --- | --- |
| 待运行 | 已保存配置，点击运行才开始 |
| 等待价差 / 等待进入区间 | 当前条件未满足，程序继续监测 |
| 连接重试中 | 临时读取失败，本次不交易，恢复后继续；连续五分钟不可用才暂停 |
| 已暂停 | 持仓保留；检查连接或参数后可点击运行 |
| 需要处理 / 订单待确认 | 原订单或仓位证据不足；同步原订单并核对交易所持仓 |
| 手续费待确认 | 成交金额已知，但实际手续费证据还不完整 |

历史通知不会因连接恢复而自动删除。最新账户与 Bot 状态用于判断当前是否仍有问题。遇到未知订单，不要通过删除 Bot、清空数据库或重复创建交易来绕过核实。

电脑休眠、网络断开或服务停止都会影响监测。地址无法访问、数据备份、服务器连接和日志查看见 [运维说明](operations.md)。
